# 地图工坊（上帝视角地图编辑器）

“地图工坊”是一个 Godot 编辑器主屏幕插件，用来可视化编辑探索地图
（`godot/data/layouts/` 下的 JSON）。它不参与游戏运行时依赖，只在编辑器里工作。

## 怎么启用

仓库已经在 `godot/project.godot` 的 `[editor_plugins]` 里启用了插件：

```ini
[editor_plugins]

enabled=PackedStringArray("res://addons/layout_editor/plugin.cfg")
```

如果插件没有出现，用 Godot 4 打开 `godot/project.godot`，进入
**项目 → 项目设置 → 插件**，勾选“地图工坊”。启用后编辑器顶部主屏幕会多出
“地图工坊”页签，点开即进入；游戏主场景与 2D/3D/脚本页签不受影响。

插件代码在 `godot/addons/layout_editor/`：

| 文件 | 职责 |
| --- | --- |
| `plugin.gd` | 主屏幕插件入口，只在这里调用 `EditorInterface` |
| `main_panel.gd` | 面板编排：画布输入、文件操作、试跑请求、地形操作转发 |
| `panel_base.gd` | 三栏 UI 骨架、素材按钮与详情/地形切换 |
| `terrain_panel.gd` | 地形工具区：台地/水面/连接表单与圈选状态 |
| `environment_panel.gd` | 环境工具区：天空/光照、相机范围与四边边界林 |
| `trigger_panel.gd` | 物件触发器小节：类型/目标/触发方式与任务参数 |
| `edit_state.gd` | 当前文档、保存快照、撤销/重做、选择与地形编译缓存 |
| `edit_ops.gd` / `edit_queries.gd` | 纯函数的文档修改与查询/坐标换算 |
| `edit_terrain_ops.gd` | 台地、水面、楼梯/坡道的纯文档操作 |
| `layout_files.gd` | 地图列表、新建、保存、试跑快照 |
| `map_grid.gd` / `palette_button.gd` | 俯视网格画布、地形叠层与素材按钮 |

## 界面

- **顶部**：地图列表（读取 `res://data/layouts/*.json`）、新建、保存、撤销、重做、试跑。
  右侧显示“已保存 / ● 未保存的修改”。
- **左栏**：分类筛选与素材按钮。上方是地面材料，下方是物件。点击素材后点格子放置，
  也可以直接拖到具体格子。
- **中间**：真实俯视网格，可滚动、可缩放；显示格坐标、地面颜色、物件占地与朝向、
  选中/悬停足迹和区域虚线。放置预览为绿色，非法位置为红色斜纹。
- **右栏**：顶部可在“详情”“地形”“环境”之间切换。详情页有地图 ID/名字/格数（应用时整体校验）、当前对象坐标/朝向/标签、
  物件触发器小节（见下文“物件触发器”）、快捷按钮（选择、移动、旋转、删除、放出生点）以及区域标注；
  地形页见下文“地形：台地、楼梯/坡道与水面”，环境页见下文“环境：天空、光照、相机范围与边界林”。
- **底部状态栏**：显示“已保存”“修改未保存”“坐标”和每次操作的成功/失败原因。

常用操作：

- 地面：选择地面材料后按住左键拖动整片刷涂；一笔只算一次撤销。
- 物件：选中素材后点格子，或从素材栏拖到目标格；纯“选择”模式不会重复放置。
- 右键：擦掉该格地面，以及包含该格的物件。
- 选中：点物件占地内任意一格（含旋转后的范围）即可选中；再点“移动”后点目标格完成两步移动。
- 旋转：选中后点“旋转”或按 `R`，每次转 90°。
- 区域：输入区域名，点“添加区域（点两个角）”，再点两个格子。区域只作标注，不阻挡通行。
- 删除：选中物件/区域后点“删除”或按 `Delete`；出生点只能移动不能删除。
- 快捷键：`Ctrl+S` 保存、`Ctrl+Z` 撤销、`Ctrl+Shift+Z` / `Ctrl+Y` 重做、`G` 选择模式；
  输入框获得焦点时不会触发字母快捷键。

## 怎么搭紫霞派

1. 打开“地图工坊”，顶部地图列表默认进入 `zixia_sect`（紫霞派）。
2. 左栏选择地面材料（例如“石板”），在中间网格上按住左键拖出前院与山道。
3. 从物件列表选择“大殿”“山门牌坊”“石墙”“松树”等，放到对应格子；放置前可用
   红/绿预览确认占地不越界、不与其他物件重叠、不挡出生点。
4. 选中物件后用“旋转”调整朝向，用“移动”微调位置，右侧可改标签（例如“下山”）。
5. 用“放出生点”把出生点放到山门内的空地上（出生点显示为格坐标，JSON 里存世界单位）。
6. 输入区域名，点两个角添加“大殿”“前院”“练功场”“山门”等标注。
7. 点“保存”。第一次保存会写到 `res://data/layouts/<id>.json`。

## 地形：台地、楼梯/坡道与水面

地形工具区在右栏。点顶部工具栏的“地形”按钮，或右栏顶部的“地形”切换页签，
它会在滚动内容顶部立即展开；点“详情”回到原来的对象/区域面板。左侧素材栏、
中间俯视网格和缩放保持不变，素材仍可直接拖到画布。

### 圈台地

1. 在“台地”表单填写名称、顶部高度、下层高度和顶面材料。
   - 顶部高度使用 0.5 单位增量，必须大于下层高度，上限 24。
   - 下层高度默认 0（平地），同样使用 0.5 增量。
   - 顶面材料只列出素材目录中 `kind: ground` 的地面项；不选时沿用地图地面。
2. 点“圈台地”，在画布上点两个对角格（两端格都包含），再在表单点“应用”前的
   高度/材料就是这次写入的值。第二次点击时立即提交；失败时状态栏说明原因，
   当前文档和撤销历史保持不变，起点角保留，可以继续点另一个对角重试。
3. 画布按世界坐标写入 `terraces[].rect = [x0,z0,x1,z1]`，两角自动对齐 2 单位格边。
   可以重复圈多层；不同台地面积不能重叠，可以共享边。
4. 在列表选中台地后可修改名称/高度/材料，点“应用”。应用只改这些字段，
   保留原有 `rect` 和 `stairs`，不会清掉已有连接；若新高度使连接接合失效，
   完整校验会拒绝这次修改并说明原因。
5. 选中台地后点“删除台地”；删除同时移除它自己的 stairs，不影响其他台地。

### 圈水面

1. 在“水面”表单填名称；“自动水位”默认勾选，水位取水面底面 + 0.05。
2. 取消“自动水位”后可以填显式水位（0.25 增量）。显式水位必须高于水面底面。
3. 点“圈水面”，同样点两个对角格（含两端格）。水面矩形对齐格边，跨越高差、
   与已有水面重叠、压住物件或出生点都会被拒绝。
4. 列表选中水面后可以“删除水面”。

### 楼梯 / 坡道连接

1. 先在台地列表选中一个台地；连接会写进该台地的 `stairs` 数组。
2. 在“连接（楼梯 / 坡道）”里选类型：
   - 楼梯按每阶 0.5、进深 1 计算，选项文字会显示实际级数与向外深度。
   - 坡道按高差 × 3 计算向外深度（至少 1），选项文字显示实际深度。
   方向默认“自动方向”；在台地角落或单格宽/单格深的边缘会产生歧义时，
   改选“南/北/东/西”明确方向。
3. 点“放连接（点两格）”，在画布点台地同一条边缘上的起点格和末尾格；
   单格宽连接可以把同一格点两次。
4. 完整校验会检查：两格在同一侧边缘、连接完全在地图内、低侧地面等于该台地的
   下层高度、不与其他连接/水面重叠、不压住物件。失败时状态栏给出原因，
   文档、历史和起点格都保留，可以继续点另一格。
5. 连接在工具区有独立列表，显示所属台地、方向、类型和开口宽度；选中后点
   “删除选中连接”。删除连接只会移除对应 stairs 项，不影响台地或其他连接。

### 画布叠层与性能

- 台地按高度着色并标注名称/顶部高度/下层高度；连接显示投影矩形、向外箭头和
  “楼梯 N 级 / 坡道 · 深 X”；水面显示蓝色范围。叠层画在网格和物件下面，
  名称/方向标在物件之后但低于选中/悬停提示。
- 圈选时画布显示半透明矩形预览：绿色可提交，红色表示越界或与同类地形重叠。
- 鼠标停在任何格子上都会在中间栏和地形工具区显示该格地面高度。
- 地形只在文档实际改变或整图刷新时编译一次；hover、绘图预览和重绘都读缓存，
  不会每格重新编译或校验。
- 新放的物件、NPC、出生点仍由运行时的地形高度定位，不需要在编辑器里单独抬高。

半途操作（已点一个角或连接起点）在按 `Esc`、切换模式、切换地图或撤销/重做时
自动清理；状态栏会提示取消。只有成功的提交进入撤销历史。

### 试跑

地形草稿同样走“试跑”：快照写入 `user://map_editor_playtest.json`，
试跑场景按完整格式加载台地、挡墙、楼梯/坡道和水面；角色可以沿连接上下，
普通台地边缘阻挡通行，水面默认阻挡。正式地图 JSON 不会被本次试跑改动。



- 保存路径固定为 `res://data/layouts/<id>.json`；ID 只能用小写字母、数字和下划线，
  且以字母开头，因此无法通过 ID 穿越目录。
- 保存允许覆盖“当前打开的同 ID 文件”。把 ID 改成另一个已存在的文件会拒绝，
  避免误覆盖别人的地图。
- 新建、打开另一张地图时，如果有未保存修改会先询问是否放弃；取消会保留当前草稿。
- 缩小地图格数时，如果有地面/物件/区域/出生点会被裁掉，整次修改被拒绝并说明原因。
  请先清理相关数据再缩小。
- 编辑过程不写任何 JSON；只有“保存”和“试跑”会落盘。

## 环境：天空、光照、相机范围与边界林

环境工具区在右栏。点顶部工具栏的“环境”按钮，或右栏顶部的“环境”切换页签，
它会在滚动内容顶部立即展开；点“详情”或“地形”切回其他页面。环境与地形共用同一张
俯视画布，不会同时占用画布输入：开始框选相机范围时，未完成的地形圈选会先取消。

### 天空与光照

- “天空”可选：默认、晴空、黄昏、夜晚。
- “光照”可选：默认、暖光、冷光、夜色。
- 天空与光照分开保存；没有配置的地图在试跑时使用与旧版完全相同的默认天空和光照。
- 选择后点“应用环境”一次性写入，不会在每次下拉切换时频繁改文档。

### 边界林

- 勾选“北 / 东 / 南 / 西”中需要铺树的边；全不勾等于关闭边界林。
- “林带深度”是树带向地图外延伸的距离，“树木间距”控制疏密；数值过小、树太多时
  应用会被校验拒绝，并提示减少深度或增大间距。
- 边界林只在地图外生成背景树，不参与碰撞；树根会贴合地形边缘高度。
- 已配置的随机种子会保留；第一次配置时使用默认种子。

### 相机范围

- 点“框选相机范围”，在画布上点两个对角格（含两端格）。框选过程中画布显示紫色描边，
  应用后已提交范围显示蓝色描边。
- 相机范围只限制镜头取景，人物的可通行范围仍由地图边界和地形决定。
- 点“清空范围”只清除表单里的范围，再点“应用环境”才会写掉文档中的 `camera_clamp`。

### 应用、撤销与试跑

- “应用环境”把天空、光照、相机范围和边界林作为一个编辑事务提交：先校验草稿，
  失败时状态栏说明具体字段并保留原文档；成功后进入撤销历史。
- “清空环境配置”移除整个 `environment` 字段，同样可以撤销。
- 试跑快照 `user://map_editor_playtest.json` 会带上完整环境字段，正式地图不会被本次试跑改动。
- JSON 字段（全部可选，缺省沿用当前默认）：

```json
"environment": {
  "sky": "default",
  "lighting": "default",
  "camera_clamp": [x0, z0, x1, z1],
  "border": {"sides": ["west", "east", "south"], "depth": 14, "spacing": 3.2, "seed": 7}
}
```

## 物件触发器

选中地图上的任意物件实例（NPC、建筑、道具、出口等）后，右栏“详情”页会出现
“物件触发器”小节。同一种素材的不同实例各自保存触发器，互不继承；新放置或复制出来
的实例默认没有触发器。

### 表单

- **类型**：对话、遭遇、出口、任务。
- **触发方式**：按键互动（`interact`，运行时按 E）或进入感应圈（`enter`）。
  进入只在从圈外走进来时触发一次，离开后可以再次进入。
- **目标**：可从下拉列表浏览现有内容，也可以直接输入 ID。目标只接受安全 ID，
  不需要也不允许写 `res://` 路径。
  - 对话：`data/dialogues/` 下的文件名 ID（不含 `.json`），例如 `npc_disciple`。
  - 遭遇：`data/enemies.json` 中的敌人 ID，例如 `bandit`；可设置 1..5 个。
  - 出口：`town` / `tavern` / `forest`，或已存在的 `data/layouts/<id>.json` 地图 ID。
  - 任务：`data/quests.json` 中的任务 ID；动作可选“开始任务”或“交付任务”。
- **应用触发器**：把当前表单作为一次编辑提交，可用 `Ctrl+Z` 撤销、`Ctrl+Shift+Z` / `Ctrl+Y` 重做，
  也会随“保存”和“试跑”一起生效。
- **清空触发器**：删除该实例的 `trigger` 字段，同样可撤销。

校验会检查触发器结构、允许的类型/触发方式/任务动作，以及目标是否真实存在。
应用失败时状态栏给出具体原因，当前文档、撤销历史和表单草稿都保持不变。

### 数据格式

```json
"objects": [
  {
    "asset": "disciple",
    "x": 5,
    "z": 6,
    "turn": 0,
    "label": "守门弟子",
    "trigger": {
      "kind": "dialogue",
      "target": "npc_disciple",
      "activation": "interact"
    }
  },
  {
    "asset": "sect_exit",
    "x": 4,
    "z": 8,
    "turn": 0,
    "trigger": {"kind": "exit", "target": "town", "activation": "enter"}
  }
]
```

- `trigger` 完全可选；没有该字段的旧地图继续按原来的 NPC/出口预览逻辑运行。
- 遭遇可带 `"count": 1..5`；任务可带 `"action": "start" | "turn_in"`。
- 运行时互动半径固定（与原有互动半径一致），并检查地形高差；台地上下隔开时不会跨层触发。
- 读取与校验只使用现有 `Dialogue`、`DataLoader`、`Quests` 数据定义，不写游戏状态。

### 试跑与正式运行

- 试跑（`res://tools/layout_playtest.tscn`）会设置 `playtest_mode`：
  - 对话使用真实 `DialogueView` 播放，可实际按 E 推进；
  - 遭遇/任务/出口只弹出确认提示，不进入战斗、不改任务状态、不切换场景、不写存档。
- 正式布局（`features/layouts/layout_walk.gd`，`playtest_mode = false`）：
  - 遭遇通过 `encounter_requested` 信号交给 app 的现有 Game / BattleFlow；
  - 出口通过 `exit_requested` 信号交给 `SceneRouter`，目标为 `town` / `tavern` / `forest`
    或另一张布局；
  - 任务直接调用现有 `Quests.start()` / `Quests.turn_in()`，并通过 `quest_resolved` 返回结果。
- 正式布局战斗结束会回到原布局 ID；返回位置仍在地图内且不压阻挡时沿用，否则回到地图出生点。
  返回时已处在同一个进入感应圈内不会立刻重触发，离开后可再次触发。

## 怎么试跑

点顶部“试跑”：

1. 当前草稿（**包括未保存的修改**）先写到独立快照 `user://map_editor_playtest.json`；
2. 编辑器运行 `res://tools/layout_playtest.tscn`，该场景的 `map_path` 指向上述快照；
3. 正式地图 `res://data/layouts/*.json` 完全不会被改动。

注意：

- 如果编辑器里已经有游戏在运行，插件会拒绝试跑并提示先停止当前运行，避免打断已有游戏。
- 直接运行 `main_panel.tscn` 只能编辑；试跑请求由插件接收，独立运行时不会调用编辑器接口。
- 试跑快照与正式存档分离，试跑里的移动/互动不会写回地图或存档。
- 试跑场景以 `playtest_mode = true` 运行：对话真实播放；遭遇/任务/出口只确认目标和触发条件，
  不进入战斗、不改任务状态、不切换场景。

## 怎么加素材

1. 把图片放到 `godot/assets/` 下（地面常用 `textures/`，物件常用 `scenery/`、`sprites/`）。
2. 在 `godot/data/layout_catalog.json` 的 `items` 里加一条：
   - `id`：稳定的小写 ID，编辑器与地图 JSON 都按它引用；
   - `name` / `category`：显示名与左栏分类；
   - `kind`：`ground`、`box`、`billboard`、`npc`、`exit`、`scene`；
   - `size`：占地格数 `[宽, 深]`；
   - `texture`（地面/box）或 `sprite`（billboard/npc/exit）、`height`、`blocking`。
   - `scene` 项的根节点须是 `Node3D`，原点放在占地中心的地面处。把 `.tscn` 放在 `shared/scenery/layouts/prefabs/`，或把导入为场景的 `.glb` 放在 `assets/`。填写 `scene` 路径，可用 `texture` 提供缩略图。木人桩是现成示例。
3. 重新打开面板或重新加载地图（切换一次地图即可），素材按钮与缩略图会刷新。
   编辑器的缩略图按目录图片路径缓存，不会每次重画都读磁盘。

## 怎么接主线

- 运行侧统一通过 `core/layouts/layout_document.gd` 与
  `shared/scenery/layouts/layout_builder.gd` 读取地图，不要复制 JSON schema。
- 现有运行场景是 `features/layouts/layout_walk.tscn` / `layout_walk.gd`；
  它通过导出的 `map_path` 指向地图 JSON。试玩变体 `tools/layout_playtest.tscn`
  只把 `map_path` 指到 `user://map_editor_playtest.json`。
- 主线接入时，把 `map_path` 指向保存后的 `res://data/layouts/<id>.json`，
  或在 `app/` 的编排里切换场景并传入地图路径；编辑器本身不需要进入游戏依赖图。
- 已经提供可复用的 app 路由入口：`app/game.gd` 的 `show_layout(map_id, return_pos = null)`
  和 `app/scene_router.gd` 的同名方法。`map_id` 只能是 `data/layouts/<id>.json` 的安全 ID；
  布局里的出口/遭遇信号由 router 交给现有 `SceneRouter` / Game / BattleFlow。
  地图作者将来在主线里调用这个入口即可，不需要改布局场景本身。
- 新增/修改地图后，运行 `npm run check:godot`，并补 `godot/tests/` 下的地图测试。

## 当前限制

- 固定每格 2 个游戏单位；台地/水面矩形对齐格边，高度使用 0.5 单位增量。
  旧地图没有地形字段时继续按 0 高度平地读取。
- `spawn` 在 JSON 中是世界单位坐标；编辑器内部与画布统一显示为格坐标，
  保存时再写回 `(格 + 0.5) * 2`。不要让界面同时暴露两套坐标。
- 区域只用于编辑标注与试跑提示，不参与碰撞或玩法判定。
- 地面是单格覆盖：同一格重复铺只会替换材质；物件不能互相重叠。
- 环境字段全部可选；旧地图没有 `environment` 时继续使用当前默认天空/光照、不夹取相机、不建边界林。
- 撤销历史上限 100 条（整笔刷涂算一条）。
- 编辑器不做自动保存；关闭编辑器前若有未保存修改，插件会通过
  `_get_unsaved_status` 提醒，避免悄悄丢草稿。

## 下一批开发交接

### 1. 地形高度与通行

> 当前状态：编辑器侧已实现（见上文“地形：台地、楼梯/坡道与水面”）。下面是原始设计目标。

紫霞派按山脚加三层台地规划。山脚是入门弟子生活区，第一层是炼体中级弟子的住处和练武场，
第二层安排人杰弟子的小院，第三层留给师傅。层数、高差、范围和建筑位置都由地图作者在工坊里定。

- **工坊操作**　沿用俯视网格。先点两个角圈出台地，输入名称和相对地面的高度，再沿台地边缘放楼梯或坡道。
  画布显示台地范围、高度和连接方向。新放的建筑、树木、NPC 和出生点随地面高度落位。
- **数据对齐**　参照 `godot/data/town.json` 的台地矩形、目标高度 `y`、低侧高度 `from_y`
  和楼梯开口 `stairs`。画布负责格坐标转换，数据层统一查询世界坐标的地面高度。
  优先复用小镇已有的台阶尺寸和挡墙开口逻辑。现有地图缺少地形字段时继续按平地读取。
- **试跑行为**　生成台地顶面、挡墙及连接处。人物可以沿楼梯或坡道上下，普通台地边缘阻挡通行。
  水面有独立的范围和水位，默认阻挡通行，为后续桥面留接入位置。
- **验收**　在独立测试地图放三层台地，验证上下楼、坡道通行、挡墙阻挡、水面阻挡、物件落位，以及旧平面地图读取。
  从编辑器圈出台地后可以撤销、重开并恢复，也可以直接用草稿试跑。正式紫霞派地图的布局由作者保存。

### 2. 环境设置

> 当前状态：编辑器侧已实现（见上文“环境：天空、光照、相机范围与边界林”）。下面是原始设计目标。

给每张地图配置边界林、天空、光照和相机范围。边界林与相机范围沿用小镇 `border` 和
`camera_clamp` 的含义。相机范围用于限制取景，人物的可通行范围仍由地图边界和地形决定。
天空和光照先提供可直接选用的预设，旧地图继续使用当前默认环境。

### 3. 物件触发器

> 当前状态：已实现（见上文“物件触发器”）。下面是原始设计目标。

选中地图上的物件实例后绑定对话、遭遇、出口或任务，通过对应内容的 ID 接入现有系统。
例如按键与守门弟子对话，或走进练武场触发指定遭遇。同一种素材的各个实例可以绑定不同内容。
编辑器检查引用是否存在，正式游戏由现有场景、对话和任务逻辑执行。

### 4. 素材登记接口

新增图片的登记脚本由地图作者提供，输出沿用 `godot/data/layout_catalog.json` 的条目。
脚本生成稳定的素材 ID 和图片路径，占地、碰撞和展示类型留给作者确认。已有 ID 保持稳定，确保已摆放的物件可以继续加载。
